# Poster Bot

Telegram-бот для одного владельца и одного канала: черновики,
предпросмотр, публикация по почасовым слотам или в выбранное время.
Управление — в личном чате с ботом: дневной план, редактирование,
отмена, история и журнал отправок.

Пересылка имеет два явных режима: подписанная копия и нативная пересылка
оригинала без добавления подписи. Для обычных публикаций и копий подпись
настраивается через окружение. Неопределённый результат отправки не приводит
к слепой автоматической повторной отправке: это снижает риск дубликатов,
но не является гарантией exactly-once со стороны Telegram.

## Требования

- Python 3.10–3.14; aiogram 3.31.0 закреплён в `pyproject.toml`.
- Для контейнерного запуска — Docker и Docker Compose 2.30+
  (`compose.yaml` использует `env_file.format: raw`).
- Токен Telegram-бота, числовой ID владельца и канал, в котором бот
  назначен администратором с правом публикации; исходящий HTTPS.

## Настройка

Для новой установки скопируйте шаблон; существующий `.env` не перезаписывайте:

```bash
cp -n .env.example .env
chmod 600 .env
```

Заполните `.env` своими значениями (не публикуйте файл и токен):

- `POSTER_BOT_BOT_TOKEN` — токен бота.
- `POSTER_BOT_OWNER_USER_ID` — положительный числовой ID владельца.
- `POSTER_BOT_CHANNEL_ID` — числовой ID канала либо его публичное имя;
  для приватного канала нужен числовой ID.
- `POSTER_BOT_SIGNATURE_MAIN_TEXT`, `POSTER_BOT_SIGNATURE_MAIN_URL`,
  `POSTER_BOT_SIGNATURE_PARTNER_TEXT`, `POSTER_BOT_SIGNATURE_PARTNER_URL` —
  все четыре поля подписи для планирования подписанных публикаций.

Часовой пояс, границы слотов и локальные пути БД/блокировки описаны
в `.env.example`. Compose задаёт пути внутри постоянного тома самостоятельно.

## Запуск и обслуживание

**На один токен допустим только один poller, включая другие компьютеры
и контейнеры.** Перед запуском убедитесь, что другой экземпляр остановлен.
Для локальных экспериментов используйте отдельный тестовый токен и канал,
не рабочие учётные данные и не рабочую БД.

Команды из каталога проекта после настройки:

```bash
docker compose up -d --build bot
docker compose logs --tail=100 bot
docker compose stop bot
```

Базовый Compose не включает автозапуск (`restart: "no"`). Логи могут содержать
приватные данные: не публикуйте их без очистки.

SQLite и файл блокировки сохраняются в постоянном томе Docker; локальные
пути по умолчанию находятся в `data/`. Сохраняйте `.env`, данные и резервные
копии отдельно от исходников. **Не выполняйте `docker compose down -v`: это
удаляет том с данными.** Перед обновлением существующей БД остановите бот,
сделайте согласованную резервную копию и проверьте совместимость и необходимые
миграции версии. Не подменяйте заполненную БД новой и не возвращайте старую
копию после новых отправок: это может вызвать повторные эффекты.
