# PLAN.md — Poster Bot

Бот публикации постов одного владельца в один Telegram-канал.
Термины — в [GLOSSARY.md](./GLOSSARY.md). Текущий runtime и завершённые
этапы описаны в [README.md](./README.md); здесь — только незавершённые
задачи.

Легенда: `[ ]` — запланировано; `⛔` — ждёт решения владельца.

## Проверки и выпуск

- [ ] Завершить проверку замороженного локального состояния: полный офлайн-прогон,
  независимое ревью и security-проверку preview, редактирования, нативной
  пересылки и свежих «Отмена»/«Назад»; разобрать замечания до выпуска.
- ⛔ Владелец должен отдельно определить числовой id приватного канала и
  права бота-администратора, согласовать конфигурацию и повторную проверку
  старта. Последний проверенный серверный старт был заблокирован каналом;
  последующие ручные действия не проверены.
- [ ] Выпуск на сервер `example-server` — только по отдельному разрешению
  владельца после проверок и решения блокера: согласованная резервная копия,
  совместимый сохранённый образ, перенос нужных исходников, сборка и один
  poller. После любого сохранённого native-ввода/плана/намерения/UI слепой
  откат на старый образ небезопасен даже без очереди; старую БД после новой
  активности не восстанавливать. `.env` не переносить/не синхронизировать без
  отдельной явной команды; автоматического обновления нет.
- [ ] Живая приемка в реальном Telegram: preview на каждом этапе, замена
  полного стека, оба явных режима пересылки, полный альбом, сохранность
  источников, три режима редактирования, свежие «Отмена»/«Назад», выбор
  времени и финальное подтверждение, дневной план и навигация. Только с
  разрешения владельца, без автоматического запуска тестового канала.

## Отдельные команды и согласования

- [ ] По отдельной команде: сохранить принятые изменения в Git (commit/push).
- [ ] Согласовать окно проверки автозапуска после физической перезагрузки:
  общий Docker daemon с шестью другими сервисами, `restart: unless-stopped`.
  Ручной `stop` остаётся остановленным; без окна и разрешения не перезагружать.
- [ ] Оператору отдельно рассмотреть регулярное расписание резервных копий;
  cron/автоматические backup сейчас не настроены.
- ⛔ Если остаётся актуальным, условное security-замечание по host/Docker
  (netdata, root trust) — только решение владельца, не исправлять без команды.
- ⛔ Отдельное согласование, не запланированная работа: PostgreSQL, если
  появится необходимость. Текущий runtime — SQLite.
